What does this mean?
“width=device-width”– width of page is the same as width of viewport
MY WEBSITE ADAPTS TO THE WIDTH OF THE DEVICE
ex: if the viewport is 325px wide, the page will display as 325px wide
“initial-scale=1.0” – page should not zoom in/out when first loaded.

place the gifs side-by-side to compare the difference between fixed/fluid/responsive

fixed – this is us now

fixed layouts rely on a static container with a fixed pixel width. resizing browser has no impact

fluid – we kinda know this

fluid layouts use relative units and the layout increases/decreases with the browser window. layout breaks at small scale

responsive – GOALS

responsive web design is about using HTML and CSS to automatically resize, hide, shrink or enlarge a website to make it look good across all devices.

Reflection: The original layout began to break at about half of the screen. I picked 900px and 600px at my two breakpoints, because one is for tablet size and one is for phone size. At the 900px breakpoint, I changed the font size to 70% and made the images width to 100% to fit the screen size. At the 600px breakpoint, I changed the font size to 50% and made the images width to 100% as well. I think everything is easy to make responsive because you can just use presentation to adjust the size of everything. I don't think there is anything hard to make it responsive, you just have to keep adjusting the numbers till you are happy with it. I don’t think this is hard but it does take time to do it. I understand now that the 3 of them work together as a system. Flexbox controls how items line up in rows or columns. Relative units allow those items to scale smoothly as the window changes. Media queries are like the final switch, when the screen gets too small and the Flexbox layout can no longer fit, media queries trigger to change the font sizes and force things to stack or resize.
